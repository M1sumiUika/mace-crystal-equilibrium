# 原理说明：从晶体结构到平衡性质

本项目计算固定晶体相、静态晶格、近似零温条件下的能量曲线。输入是原子种类、原子位置、晶胞和周期性边界；输出是 MACE 力场预测的能量、力和应力。随后用数学拟合提取平衡性质。这里没有执行新的 DFT 计算，也没有训练或微调 MACE。

## 1. MACE 如何预测能量、力和应力

可以把晶体理解为按一定规则无限重复的小盒子。MACE 读取每个原子及邻域的化学种类、距离和方向，使用多体特征及等变消息传递描述局域环境，再把原子能量贡献相加得到总势能。旋转整个晶体不应改变能量，而力向量应随晶体一起旋转；等变结构把这类对称性写入网络。[MACE 原始论文](https://arxiv.org/abs/2206.07697)

力由能量对原子位置的负导数给出：

\[
\mathbf F_i=-\frac{\partial E}{\partial\mathbf r_i}.
\]

周期体系的应力与能量对应变的导数有关。MACE 使用自动微分计算这些导数，所以“能量导数与应力是否一致”是接口和数值实现的重要检查；通过它并不等于已经验证模型符合真实材料。模型参数来自既有训练数据，预测仍可能带有训练方法的系统偏差。[MACE 官方计算器源码](https://github.com/ACEsuit/mace/blob/v0.3.16/mace/calculators/mace.py)

本项目指定 `device="cuda"`，把模型和实际输入张量放在 NVIDIA GPU 上。ASE 建结构、SciPy 拟合和 Matplotlib 绘图使用 CPU。GPU 不是物理模型的一部分，它承担神经网络计算；改变精度可能带来数值差异，因此需要 float32/float64 对照。

## 2. 晶胞、体积与晶格常数

正式扫描采用立方常规晶胞：金刚石结构 Si 含 8 个原子，面心立方 Al 含 4 个原子。对立方晶胞，体积为 \(V_\mathrm{cell}=a^3\)。记原子数为 \(N\)，每原子体积 \(v=V_\mathrm{cell}/N\)，则

\[
a=(Nv)^{1/3}.
\]

初始晶格常数 `Si = 5.43 Å`、`Al = 4.05 Å` 只是便于开始扫描的近似猜测，不作为实验参考值或拟合结论。若体积乘以 \(s\)，晶格常数应乘以 \(s^{1/3}\)。例如体积增加 10%，边长只增加约 3.23%，不能把体积比例直接当作边长比例。

程序使用 `set_cell(..., scale_atoms=True)` 同步缩放晶胞和原子位置，因此原子的分数坐标保持不变。每一个扫描点都是指定体积下的一次计算，扫描中不放开晶胞体积。等价原胞、常规胞和超胞描述同一无限周期体系，正确实现应给出一致的每原子能量和应力；总能量随原子数变化。

## 3. 为什么最低点对应平衡体积

外压为零时，在指定晶相和变形路径下，稳定的平衡体积使势能最低：

\[
\left.\frac{dE}{dV}\right|_{V_0}=0,\qquad
\left.\frac{d^2E}{dV^2}\right|_{V_0}>0.
\]

压得过紧或拉得过松都会提高附近的能量。在多个体积上实际调用 MACE 得到离散的 \(E(V)\) 点，再拟合平滑曲线，便可求得最低点。扫描边界上的最低值不可靠：真正最低点可能位于区间外，因此程序必须扩展区间；包围最低点后再加密附近的扫描。

本项目使用每原子能量 \(e=E/N\) 和每原子体积 \(v=V/N\) 拟合，二者的归一化必须一致。若把总能量和每原子体积混用，导数及体模量就会错误地多出原子数因子。Si 和 Al 的绝对能量零点不同，图中分别减去各自最低能量，不能从两条曲线的绝对高低判断哪种材料“更稳定”。

## 4. 状态方程与体模量

三阶 Birch–Murnaghan 状态方程的每原子形式为

\[
e(v)=e_0+\frac{9v_0B_0}{16}\left[
(\eta-1)^3B'_0+(\eta-1)^2(6-4\eta)\right],
\qquad \eta=(v_0/v)^{2/3}.
\]

\(e_0\) 是最低每原子能量，\(v_0\) 是平衡每原子体积，\(B_0\) 是零压附近体模量，\(B'_0=(dB/dP)_{P=0}\) 为无量纲的压力导数。代码还使用 Vinet 方程作对照；两种形式均是对曲线的近似，并不自动保证模型准确。[ASE 状态方程接口与方程来源](https://docs.ase-lib.org/ase/eos.html)

压力和体模量满足

\[
P=-\frac{dE}{dV}=-\frac{de}{dv},\qquad
B=-V\frac{dP}{dV}=V\frac{d^2E}{dV^2}
=v\frac{d^2e}{dv^2}.
\]

体模量越大，产生同样相对体积压缩所需的压力越大。在最低点附近，能量曲线越陡，抵抗均匀压缩的能力越强。只有体积方向的曲率为正，不足以证明所有剪切、声子或其他晶相方向都稳定。

体模量与杨氏模量不同：体模量描述各方向均匀受压时的体积变化；杨氏模量描述单轴拉伸时的纵向应力与应变。在立方晶体中，\(B=(C_{11}+2C_{12})/3\)，而杨氏模量还与其他弹性常数及晶向有关。仅有本项目的体积扫描，不能得到完整弹性张量或任意晶向的杨氏模量。

## 5. 应力的符号与单位

ASE 使用拉伸为正的应力约定，静水压缩为正的压力则为

\[
P=-\frac{\sigma_{xx}+\sigma_{yy}+\sigma_{zz}}{3}.
\]

`atoms.get_stress(voigt=False)` 返回完整 `3 × 3` 张量；Voigt 六分量顺序为 `xx, yy, zz, yz, xz, xy`。本项目保存完整张量，检查 MACE 计算器声明支持应力，并通过 \(-de/dv\) 的有限差分检查其符号及数值；完整张量还允许进一步检查对称性和非静水分量。这里不含原子动量造成的动力学应力。[ASE 应力接口](https://docs.ase-lib.org/ase/atoms.html#ase.Atoms.get_stress)

模型能量为 eV，长度为 Å，应力及 EOS 原始体模量为 eV/Å³。本项目按 SI 精确定义使用

\[
1\ \mathrm{eV/Å^3}=160.2176634\ \mathrm{GPa}.
\]

ASE 默认 CODATA 2014 常数给出的转换末位略有差异，约为 \(10^{-8}\) 的相对量级，远小于这里的拟合敏感性；代码统一使用上述常数。压力曲线两种算法必须使用相同转换。[ASE 单位说明](https://docs.ase-lib.org/ase/units.html)

## 6. 为什么需要这些独立检查

| 检查 | 它回答的问题 | 不能据此推出的结论 |
|---|---|---|
| 最大原子力 | 固定理想分数坐标是否留下明显内部驱动力？ | 所有振动模式都稳定 |
| 应力压力与能量数值导数 | 符号、单位、能量与应力接口是否一致？ | 模型与实验一致 |
| 拟合平衡点处压力 | EOS 最低点是否接近真实模型的零压点？ | 扫描覆盖其他晶相 |
| 直接零压晶胞优化 | 不依赖 EOS 函数的极小化是否给出一致晶格常数？ | 不同势能模型会得到同样结果 |
| 原胞、常规胞、超胞 | 周期邻居和归一化是否一致？ | 训练集外泛化能力已证实 |
| float64/float32 | 浮点舍入对导数和拟合的影响多大？ | 较高精度消除了模型误差 |
| 扫描范围、点数和 EOS 对照 | 数值结论对具体拟合选择是否敏感？ | 该变化范围等于真实预测不确定度 |

Si 的理想金刚石结构和 Al 的理想 fcc 结构在各向同性缩放后仍有很高的局域点群对称性。对保持这些对称性的势能，原子处不存在允许的非零净力方向，因此理想位置的力应接近零。必须实际检查残余力，而不能只凭对称性假定数值实现无误。这种检查也不排除对称破缺后出现更低能量。

零外压优化单独进行，并限制三个晶轴以相同比例变化、夹角为 90°；它允许体积变化来求零压点。它与固定体积扫描是不同任务，不能在每个扫描点偷偷进行全晶胞优化，否则所有体积都会塌缩到同一附近值。

拟合残差、协方差和不同设置间差异描述的是数值拟合情况。模型的物理误差需要额外的可信 DFT 或实验数据，以及更广泛、明确隔离训练数据的验证设计，不能用极小的拟合残差替代。

## 7. 静态晶格、DFT、实验与训练各指什么

静态晶格计算把原子固定在给定位置，在势能面上寻找平衡。即使物理温度为零，真实原子仍具有量子零点振动；本项目没有加入零点能及其对平衡体积的修正。有限温度实验还包含热膨胀、振动自由能和可能的电子温度效应。因此本项目结果不能直接称为室温晶格常数或室温体模量，低温实验也不能自动当作无零点效应的静态值。

DFT 从选定交换关联近似、赝势或全电子处理、k 点网格等数值条件出发求解电子结构。不同泛函和收敛设置可以得到不同的平衡参数。预训练 MLFF 则调用已学到的能量函数，通常比重新求解电子结构快，但既有学习误差，也可能继承训练数据的方法偏差。训练或微调需要样本、标签和参数优化；本项目没有这些步骤。

比较时优先使用条件相近的静态 DFT 数据，并单独记录其方法与实验温度。Si 或 Al 与某条参考值接近，只能支持这两种晶相、这组体积范围内的有限结论。由于尚未逐条核查预训练数据是否包含这些体系，本项目不称为严格的未见材料泛化测试。

## 8. GPU 时间如何理解

模型下载、模型初始化、预热、正式推理分别计时。CUDA 可以异步执行；若只记录 Python 函数返回的时刻，GPU 可能尚未算完。因此正式计时前后执行 `torch.cuda.synchronize()`，重复计时前清除 ASE 的结果缓存，防止把缓存读取误当作模型推理。

报告中的推理时间包含调用与必要数据处理的成本，并非只测一个 GPU 内核。4 或 8 个原子的小晶胞可能主要受 Python 调用、构图和数据传输开销影响。本项目没有 CPU 对照时，不声称 GPU 有特定加速比。float64 通常比 float32 更耗时、占更多显存；是否值得使用，由关键性质的实测差异决定。

实际数值、通过与未通过的检查应查看对应运行目录的报告和原始数据。本文件只解释原理，不预先填写任何实验结论。
